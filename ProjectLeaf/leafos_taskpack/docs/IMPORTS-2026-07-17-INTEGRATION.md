## Vulkan interpretation

The imported Vulkan method is a provider architecture, not a game compute kernel. It specifies:

1. A long-lived Vulkan-capable `llama-server` process.
2. Local HTTP provider calls from LeafOS.
3. CPU parsing, policy, patch, verification, and journal authority.
4. Device and provider promotion gates before Vulkan routing.

The board-game loop integration therefore keeps native game simulation CPU-authoritative and exposes a guarded local Vulkan reasoning/provider lane. Direct Vulkan game-state kernels remain a separate conformance-gated optimization.
