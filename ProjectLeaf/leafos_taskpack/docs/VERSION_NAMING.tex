\section*{Recommendation}

Do not name the current functional agent stack \texttt{0.2.2.1}. The codebase
has moved beyond the \texttt{0.2} task spine, but it has not yet earned a stable
\texttt{0.5} reliable-loop claim.

\begin{center}
\Large\textbf{Recommended functional label: \texttt{0.4.0-alpha.1 Provider Spine}}
\end{center}

For the root package, keep a separate packaging label:

\begin{center}
\texttt{0.6.0-alpha.1+root-reformat}
\end{center}

\section*{Why Not \texttt{0.2.2.1}}

\begin{itemize}
  \item Four-part numbers obscure whether the change is packaging, taskpack, model installer, or graph contract.
  \item \texttt{0.2.x} undersells the graph, provider, patch, node, and runtime work already present.
  \item The project already has explicit stage boundaries; the version should name the stage being promoted.
  \item Alpha labels are clearer than pretending staged 0.5/0.6 design is already proven.
\end{itemize}

\section*{Promotion Rule}

\begin{lstlisting}[language={}]
captured test or run artifact
  > accepted work-order result
  > implementation documentation
  > roadmap intention
  > conceptual proposal
\end{lstlisting}

No stage should be promoted from prose alone.

\section*{Version String Pattern}

\begin{lstlisting}[language={}]
<functional-stage>-<stability>.<iteration> <short-name>

Examples:
  0.4.0-alpha.1 Provider Spine
  0.4.0-alpha.2 Patch Closure
  0.5.0-alpha.1 Persistent Loop

Root packaging may add build metadata:
  0.6.0-alpha.1+root-reformat
\end{lstlisting}
