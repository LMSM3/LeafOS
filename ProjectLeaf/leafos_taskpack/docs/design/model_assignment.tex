\section{Purpose}

This document provides black-and-white ASCII tree diagrams for the LeafOS model assignment layer.

The companion files are:

\begin{itemize}
  \item \texttt{model-library.md}
  \item \texttt{model-library-real-assignments.md}
  \item \texttt{WO-006-C-model-assignment-library-script.md}
  \item \texttt{leaf\_model\_assignments.py}
\end{itemize}

The diagrams are intentionally terminal-readable. No color. No Unicode dependency. No font ritual. A small mercy from the machinery.

\section{Core Rule}

\begin{Verbatim}[fontsize=\small, frame=single]
MODEL ASSIGNMENT IS NOT JUST A MODEL NAME.

Real assignment tuple:
  model
  quant
  lane
  endpoint
  contract
  parser
  gate

Pipeline:
  model endpoint -> logical lane -> output contract -> parser -> accepted artifact
\end{Verbatim}

\subsection*{WO-006-C/D GLM Adapter Boundary}

\begin{Verbatim}[fontsize=\scriptsize, frame=single]
Z.AI / GLM is an optional OpenAI-compatible advisory adapter.

remote GLM:
  planner / reviewer / long-context advisory lane

CPU / local LeafOS:
  coder lane
  graph and filesystem authority
  parser, patch validation, gates, hashes, reports

Provider output -> file-backed provider contract -> CPU parser -> accepted artifact

The remote adapter cannot advance the graph or apply a patch by itself.
\end{Verbatim}

|

|

\section{Final Notes}

The model assignment layer is only useful if it stays strict.

\begin{Verbatim}[fontsize=\small, frame=single]
Fast model + invalid artifact = failure
Slow model + valid artifact   = useful
Parser-valid output           = currency
Raw token speed               = only a routing hint
\end{Verbatim}
